# Employee QR Entry Check

Мобильная система проверки допуска сотрудников по постоянному QR-коду каждой точки входа. QR не содержит сведений о сотрудниках и индивидуальных токенов.

## Краткий план

1. Опубликовать статический сайт через GitHub Pages Actions.
2. Подключить приложение к Supabase Auth, Postgres и приватному Storage.
3. Добавить `locations` и безопасный RPC `check_in(location_code)`.
4. Создавать точки входа и плакаты PDF из админки.
5. Сотрудникам входить по телефону и PIN через Supabase Auth.
6. Возвращать живой экран допуска, фотографию и статус.
7. Ограничить журналирование одним событием на сотрудника в минуту.
8. Оставить управление сотрудниками, фотографиями и договорами администраторам.
9. Фильтровать журнал по дате, точке и результату.
10. Проверить QR и PDF с реального телефона после настройки учётных записей.

## Новая схема QR

Каждая точка получает постоянный случайный код. Плакат ведёт на:

```text
https://platform770uz-dev.github.io/employee-qr-passes/check.html?loc=<location_code>
```

Сотрудник входит по своему номеру телефона и PIN. После входа телефон вызывает `check_in(location_code)`. Активный сотрудник получает зелёный экран, истёкший срок допуска — жёлтый, приостановленный или уволенный сотрудник — красный. Экран показывает живые часы с секундами и анимированную полосу. Повторные проверки не создают более одной строки журнала на сотрудника за минуту.

## Установка и обновление

Приложение использует существующий общий проект Supabase `yba-family-platform` (`trxnsqpdekokqvtefxlt`), поскольку свободный лимит проектов в организации исчерпан. Схема пропусков, Auth и Storage находятся в одном Supabase-проекте с YBA.

Для нового развёртывания примените миграции в порядке версий из `supabase/migrations/`:

1. `202610240001_employee_qr_passes.sql`
2. `202610240002_harden_employee_qr_passes.sql`
3. `20261024085044_employee_location_checkin.sql`

Последняя миграция добавляет точки входа, привязку Auth-сотрудника, RPC `check_in` и фото-доступ сотрудника только к собственной фотографии. Она оставляет таблицы сотрудников, договоров, Storage, RLS, существующие журналы, общий Auth-триггер и исторические QR-столбцы. Старые браузерные RPC индивидуального QR закрыты для `anon` и `authenticated`; страницы индивидуального сканирования удалены. Сканирования новой схемы добавляют `location_id`; прежние строки журнала сохраняются.

Разверните Supabase Edge Function `employee-auth` из `supabase/functions/employee-auth/index.ts` с `verify_jwt=true`. Функция проверяет сессию и роль admin, задаёт пароль Supabase Auth и связывает Auth-пользователя с сотрудником. Service-role key остаётся только в Supabase Edge Functions и не попадает в сайт.

В `assets/js/config.js` уже указаны URL проекта, publishable key и GitHub Pages URL. В публичном клиенте не размещайте secret/service-role key.

## Auth и учётные записи

1. В Supabase Auth создайте пользователя-администратора с email и паролем.
2. Скопируйте его UUID и назначьте роль:

```sql
update public.profiles
set role = 'admin'
where id = 'UUID_АДМИНИСТРАТОРА';
```

3. Для телефонного входа сотрудников должен быть включён Supabase Auth Phone provider и вход по телефону с паролем. Настройка провайдера общая для проекта YBA; проверьте её влияние на YBA перед изменением. Эта работа не меняет глобальные настройки провайдеров.
4. В админке создайте сотрудника с телефоном в международном формате, например `+998901234567`, задайте PIN и сохраните. PIN отправляется в Edge Function и хранится только как пароль Supabase Auth; поле очищается после успешного сохранения. Для сброса PIN откройте карточку сотрудника и задайте новый.
5. Вход сотрудника выполняется со страницы `check.html?loc=...`. Supabase Auth сохраняет сессию на телефоне.

PIN принимается в диапазоне 4–6 цифр. Минимальная длина пароля Supabase Auth задаётся на уровне всего проекта. Если текущая политика отклонит PIN короче шести цифр, используйте 6 цифр; не снижайте общую защиту Auth без оценки влияния на YBA. Сайт не хранит PIN и не выводит его после сохранения.

## Точки входа и плакаты

В админке создайте точку входа. База автоматически выдаст ей код и постоянную ссылку. Кнопка «Скачать плакат PDF» создаёт A4 портрет с двуязычным заголовком, названием организации и точки, QR 120 × 120 мм и QR-изображением 1200 × 1200 px с коррекцией Q. В PDF встроен Noto Sans Regular/Bold; шрифт и лицензия SIL OFL лежат в `assets/fonts/`. На плакате напечатаны три шага на русском и узбекском.

Имя файла: `poster_<название_точки>.pdf`. Для теста напечатайте на A4 с масштабом 100% и проверьте сканирование с расстояния около одного метра.

## Страницы

- `index.html` — вход администратора по email и паролю.
- `admin.html` — сотрудники, статус, телефон/PIN, фото, договоры и точки входа.
- `check.html` — вход сотрудника по телефону/PIN и живой экран для охраны.
- `log.html` — журнал для администратора с фильтрами по дате, точке и результату.

## Проверка при вводе в работу

- Создать одну точку и проверить, что ссылка в плакате содержит только `loc`.
- Добавить тестового сотрудника с телефоном и PIN; убедиться, что PIN не появляется в таблицах приложения.
- Открыть плакат телефоном, войти и увидеть зелёный экран, фото, часы с секундной стрелкой и анимацию.
- Приостановить сотрудника и повторить проверку: экран должен стать красным. Вернуть активный статус.
- Установить дату допуска в прошлом: экран должен стать жёлтым.
- Проверить появление одной строки в `log.html`; повторить вызов в течение минуты и убедиться, что в журнале нет второй строки.
- Проверить, что не-admin не читает таблицы сотрудников, договоров и журнала; фото сотрудника доступно только ему самому, договоры остаются admin-only.
- Напечатать плакат и проверить QR с расстояния около 1 м.
- Открыть `check.html` на телефоне шириной 360 px и проверить русский/узбекский переключатель.

## Допущения и границы

- Название организации по умолчанию — «Организация»; замените `organizationName` в `assets/js/config.js` на реальное перед печатью плакатов.
- `pass_valid_until` используется как дата окончания допуска и управляется администратором; после её истечения результат становится `EXPIRED`.
- Для `suspended` и `fired` RPC возвращает `SUSPENDED`, чтобы в обоих случаях вход был запрещён и экран был красным.
- Счётчик журнала ограничен одной строкой на сотрудника за скользящие 60 секунд, независимо от точки входа. Повторный RPC всё равно получает актуальный статус.
- Phone provider Auth и минимум длины пароля — настройки всего общего Supabase-проекта. Этот код их не меняет.
- Общий Auth-триггер YBA продолжает создавать legacy-профиль с ролью `guard` для новых пользователей. Новый интерфейс и `check_in` эту роль не используют: доступ сотрудника определяется по привязке Auth ID к сотруднику, единственная роль админки — `admin`.
- Форма не позволяет создавать публичные аккаунты. Администратор создаёт сотрудника и назначает PIN.

## Безопасность

В приложении остаются только рабочие поля сотрудника, телефон, даты и фото; паспортные данные и ИНН не запрашиваются. QR содержит только код точки. RLS на сотрудниках, договорах, профилях, точках и журнале сохранён; `check_in` выдаёт данные только Auth-пользователю, связанному с этим сотрудником. Договоры хранятся в приватном бакете и доступны только admin через короткоживущие signed URL.
